# 开发路线图

> 配套：[01-产品开发企划](01-产品开发企划.md) · [02-开源方案调研](02-开源方案调研.md) · [03-技术架构设计](03-技术架构设计.md)
> 原则：**每周交付一个可运行、可验证的东西**；先跑通闭环，再叠加功能；**按价值密度推进，不按模块推进**（C17）。
> v0.6（评审优化）变更：Phase 0+1 合并为 **M0「两周自用版」**；Phase 0 退出条件改为连续 5 交易日成功率 ≥ 80%（C16）；预测验证提前进 M0（C6）；Phase 2/3 不预先排期；盘中能力永久取消（C10）；Web 改 Obsidian（C9）；150 笔交易闸门（C12）。

## M0「两周自用版」：最小闭环验证（第 1–2 周）

**目标**：用最小成本回答一个问题——"这份日报是否值得每天读、是否改善了我的交易行为"。**M0 是路线图上唯一预先排期的阶段**，其后的优先级由 M0 的真实使用数据决定。

### 第 1 周：跑通数据与最小日报

- [ ] 仓库骨架 + `config/`（data_sources / quality_rules / verify_rules / signal_rules）+ `init_db.py`（三张表：quotes / trades / notes）
- [ ] akshare 数据源 PoC：日线（含后复权 adj_close）、主要指数、涨跌家数、成交额
- [ ] 质量检查三条：价格 ≤ 0 / 交易日无数据（本地日历）/ 涨跌幅超板块分档阈值
- [ ] `data_test.py`：一键输出 `market.json / stocks.json` 测试数据；输出《字段稳定性清单》（哪些字段名/单位/空值行为不可信）
- [ ] `run_daily.py` 生成 `daily.md` 初版：市场概况 + 账户体检（读 positions.yaml）+ 自选异动 + 交易频次行
- **验收**：daily.md 与行情软件核对一致；账户体检与手工核算一致；异常数据被拦截。

### 第 2 周：note / read / 昨日验证闭环

- [ ] `note.py`：盘前预先承诺 / 交易理由录入（reason 四字段，T+1 锁定）
- [ ] `read.py`：价值验收记录（"今天哪段有用"）
- [ ] **昨日验证**：前瞻结论强制携带 `prediction`（方向/口径/时限）；命中判据写入 `verify_rules.yaml` 事前锁定；日报输出昨日判定结果
- [ ] 盘前增量附页（3–5 行：隔夜美股/期指/重大消息）——akshare 全球接口顺利则本周加
- [ ] （可选）财联社源接入：只存标题/链接/自生成摘要；是否保留由 read 数据两周内决定（C17.3 折中）
- **M0 退出条件（C16/C17）**：
  1. 连续 **20 个交易日**无人值守运行成功率 ≥ 90%，且每日有 `read` 记录；
  2. 逐源记录成功率与失败原因，任一源成功率 < 80% 必须先解决或换源；
  3. 按 C5 第 8 条裁剪段落（跳过率 > 50% 直接删除，不留开关）；
  4. 据裁剪结果与 read 数据，确定下一阶段优先级。

### M0 明确不做

全球市场（第一周）、调度器、推送、信号规则对外输出、DecisionProvider、任何 Web 栈、任何 LLM 调用、完整 schema（14 表）、盘中能力（永久，C10）。

## M0 之后：按价值密度推进（不预先排期）

M0 结束时有 20 个交易日的真实使用数据（哪段被读、哪段被跳过、命中率多少），据此从以下清单中按"价值 ÷ 实现成本"取下一批。**清单仅为候选，不是承诺**。

| 优先级 | 候选功能 | 触发条件 |
| --- | --- | --- |
| 高 | **盘中止损位提醒**（C10 唯一例外） | 有持仓且设了止损位后即可做 |
| 高 | 热点段（晚报）+ 完整验证流水线（周/月命中率报告） | 昨日验证在 M0 跑通 |
| 高 | 纪律指标周报（按计划执行率/非计划笔数/止损执行率） | M0 的 trades/notes 数据积累 ≥ 1 个月 |
| 高 | 来源白/黑名单过滤 | 接入财联社或东财新闻时同步实现 |
| 中 | 静态图买卖点标注（脚本生成图片嵌入 Markdown） | 若 read 数据显示"看图复盘"高频（C9 保留判断） |
| 中 | Windows 计划任务自动化（19:00 主报 / 07:30 增量页） | M0 验证日报有价值后 |
| 中 | 盈亏来源归因（3 类理由） | 单类样本 ≥ 20 笔（样本闸门，C4） |
| 低 | LLM 溯源压缩（C13 三约束） | 有明确的高价值文本场景后 |
| 低 | 投资风格画像 | **累计 ≥ 150 笔交易 且 C5 验收通过**（C12） |
| 低 | DecisionProvider 策略插件 / 回测（backtrader） | 信号体系经命中率验证后（C12） |
| 低 | 同花顺同步（ths-favorite 自选 / 客户端只读持仓） | 累计 ≥ 150 笔交易后评估（C12） |
| 不做 | 盘中异动/公告提醒、Web Dashboard、一日三报、五维加权评分、星级评分 | 永久取消（C7/C8/C10/C11） |

## 迭代节奏

| 周期 | 产出 |
| --- | --- |
| 每日 | daily.md 主报 + 盘前增量页 + note 计划 + read 价值记录 |
| 每周 | 纪律指标周报 + 昨日验证命中率 + 数据源健康检查 |
| 每月 | 月度复盘（纪律指标为主）+ 归因（样本达标后）+ 行为指标回顾（C1.4） |

## 变更控制

- M0 边界硬约束：两周内只做 M0 清单，任何"顺手加个功能"推入价值清单排队；
- **C5 裁剪机制**：段落跳过率 > 50% 直接删除，不做优化、不留开关；
- 每两周做一次"价值回顾"：以 read 数据与行为指标（按计划执行率/非计划笔数）为准，而不是以功能数量为准。
