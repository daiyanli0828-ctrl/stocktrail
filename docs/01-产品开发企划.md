## 1. 项目背景

用户为 A 股个人投资者，近几个月持续交易，遇到的核心问题：

1. **信息分散**：行情、新闻、公告、资金流向、龙虎榜、研报、板块热点分散在多个软件和网站；
2. **噪音太多**：难以快速分辨"与我自选股相关的、重要的、可信的"信息；
3. **决策不系统**：买卖凭感觉和碎片信息，缺乏统一的决策框架、风险检查和仓位管理依据；
4. **复盘缺失**：交易记录散落，盈亏归因说不清，错误反复犯。

目标：构建一个**本地优先**的个人工具，自动化"收集 → 汇总 → 简约查阅 → 参考决策 → 复盘"流程。**定位不是"预测涨跌的黑盒 AI"**，而是帮用户建立「信息 → 判断 → 行动 → 复盘 → 改进」的个人投资闭环（Personal Investment OS）。

**本版最重要的认知修正（C1）**：一个每天推送热点与交易计划的工具，其形态会系统性抬高用户的交易频次，而个人投资者的换手率与长期收益基本负相关——**项目失败的主要形态不是做不出来，而是做出来并被用好之后用户亏得更快**。因此本版新增行为护栏章节（§2.11），并把产品优化目标从"被使用"改为"改善行为"。

## 2. 问题定义（PRD 级）

| 编号 | 问题 | 现状 | 期望 |
| --- | --- | --- | --- |
| P1 | 信息收集成本高 | 多平台人工翻看 | 自动采集（M0：akshare 单源），统一入库 |
| P2 | 信息噪音大、无汇总 | 无法快速提炼重点 | 自动分类、去重、**来源白/黑名单过滤**；热点结论带**可验证预测** |
| P3 | 决策凭感觉 | 无统一框架 | **信号清单 + 触发规则**（无加权总分）+ 风险提示 + 决策留痕 |
| P4 | 复盘难坚持、无量化 | 记录散落 | **盘前预先承诺 + 事前锁定理由** + 纪律指标 + 样本达标后归因 |
| P5 | 工具诱导过度交易（新增） | — | 行为护栏 + 行为类成功指标（§2.11） |

## 3. 产品定位与边界

- **形态**：本地优先的个人工具。**M0 为单脚本 CLI**；阅读与组织用 **Markdown + Obsidian**，**不自建 Web 前端**（C9；保留判断：M0 后若"看图复盘"为高频需求，只做静态图 + 个股单页，不引入完整前端栈）。
- **一句话**：每天一份晚间主报 + 一页盘前增量——市场概况、账户体检、自选异动、昨日验证、条件式明日计划；建议是"信号 + 条件"，不是"买入指令"；每笔交易事前留痕、事后归因。
- **边界（明确不做）**：
  - ❌ 不做自动交易、不接入券商下单；
  - ❌ 不荐股、不输出指令式买卖、不承诺收益；
  - ❌ **盘中能力永久不做**（唯一例外：持仓跌破用户事前设定的止损位时提示；执行的是用户过去的决定，不产生新决定）（C10）；
  - ❌ 输出仅为参考，决策权永远在人。

## 4. 目标用户与使用场景

- **画像**：A 股散户，1 年以上交易经验，每天愿意投入 30~60 分钟研究；苦于信息整合与纪律缺失。
- **使用场景（C8 后）**：
  1. **盘前（约 07:30 起）**：读一页**盘前增量附页**（3–5 行：隔夜美股 / 期指 / 隔夜重大消息 + 一句"昨晚的计划是否需要调整"）；开盘前用 `note` 命令记录**盘前预先承诺**（今天打算做什么/为什么/目标/止损）；
  2. **盘后（19:00 后）**：读**晚间主报**（收盘复盘 + 账户体检 + 自选异动 + 昨日验证 + 明日条件式计划 + 交易频次行），录入当日交易、做复盘；
  3. **周末**：周报、纪律指标回顾、热点命中率回顾。

> 说明：原"一日三报"（09:00/12:00/19:00）经评审推翻（C8）——两份"一页纸"之间新增信息量只有隔夜美股，阅读负担翻倍而信息量不翻倍，必然导致跳读后两份都不读；午报属盘中时段输出，与建立纪律的目标反向，永久取消。

## 5. 核心功能模块

### M1 信息收集（M0 单源起步，接口预留）

| 类别 | 数据项 | 数据源 | 阶段 |
| --- | --- | --- | --- |
| ★ 行情（A股） | 日线（复权处理）、涨跌家数、成交额、涨停/跌停 | **akshare** | **M0 唯一数据源** |
| 全球市场 | 美股指数、日经、欧洲指数 | **akshare 全球接口为主；yfinance 仅在代理可用时启用（备）**；两源均失败 → 用 T-1 数据并显式标注 | M0 第二周视情况加 |
| 新闻热点 | 财经要闻、财联社电报（只存标题/链接/自生成摘要） | cailianpress-unified（可选） | M0 第二周视 read 数据决定 |
| 公告/财务/龙虎榜/资金 | 业绩预告、增减持、解禁、龙虎榜、资金流 | akshare | M0 后按价值密度加 |
| 实时行情/研报/问财/同花顺数据 | 扩展能力 | efinance / tushare / pywencai / Financial-API | 150 笔交易后评估（C12） |
| 自选股池 | `watchlist.yaml` 手动维护 | 本地文件 | M0 |
| 持仓 | `positions.yaml`（手动快照） | 本地文件 | M0 |
| 同花顺账号 | 自选/持仓（只读） | ths-favorite / 客户端只读自动化 | 150 笔交易后评估（C12） |
| 自定义数据源 | 用户自有/付费 API | config 注册 | 接口预留 |

要点：
- **M0 只用 akshare 一个数据源**（C17）；财联社列为 M0 第二周**可选增强**，是否保留由 read 数据决定；
- 全球数据主备调换（C14）：Yahoo 国内直连基本不可用且限流封 IP 常态化；两源均失败时降级为 T-1 数据并在报头显式标注"全球数据为 T-1，来源 X 失败"；
- **复权处理（D1）**：后复权价用于全部指标计算，不复权价用于展示；除权日从价格跳变检查中豁免；
- 统一适配层 + 自动降级（接口预留）；遵守频率限制、本地落库、全库 UTC。

### M2 汇总整理（白/黑名单 + 可验证结论 + 预测验证）

- **标准化 / 去重合并 / 自动分类**（政策/业绩/资金/公告/舆情/技术 + 利好利空倾向，规则实现）；
- **来源白名单 / 黑名单（C11）**：二值过滤，黑名单来源直接不入库；`source_credibility` 字段只存 `trusted / unknown / blocked`——星级→权重的映射无法校准，二值过滤达成同样目的且行为可预测；
- **全球市场分层**：A股大盘、美股大盘、日股/欧洲大盘与板块（数据可用时）；
- **热点结论（仅晚报）**：规则初筛 →（可选 LLM 溯源压缩）→ 输出"结论 + 板块真实数据 + 依据"；**任何进入日报的前瞻性结论必须携带可验证的 `prediction`（有方向、有标的口径、有时限），无 prediction 的结论不允许写入日报**（C6）；盘前不做热点初筛（盘前只有"昨日热点会否延续"这一假设，把假设当结论输出既无信息量又污染命中率基线）；
- **昨日预测验证（C6，提前到 M0）**：昨日结论 vs 今日实际 → 判定正确/错误；**命中判据事前写入 `config/verify_rules.yaml`**（如"次日概念指数相对沪深 300 超额收益 > +1% 记命中"），代码只读 config，判据变更留版本记录——防止看到结果后再定判据；
- **摘要生成**：规则模板（MVP）；LLM 接口预留（§2.5 M4 下方 LLM 约束）。

### M3 简约查阅（晚间主报 + 盘前增量页）

**M0 交付：`daily.md` 主报（盘后生成）+ 盘前增量附页（3–5 行）**，输出到 Obsidian vault 目录（C9）。

主报五段（C2 调整）：

1. **市场概况**：涨跌家数、成交额、涨停/跌停、热点集中度；
2. **账户体检（新，M0 即含）**：总仓位 % 与档位上限对比 / 单票占比超限项 / 第一大行业集中度 / **已跌破自设止损位的持仓** / 浮盈浮亏分布 / 持仓平均天数；
3. **自选异动**：自选股"上涨原因 / 风险 / 当前状态"（由账户体检取代原第二段位置）；
4. **昨日验证**：昨日热点结论 vs 今日实际（命中/未命中，附判据）；
5. **我的明日计划**：条件式观察计划——"若持仓：跌破 20 日线 → 风险关注；观察点：XXX"（**"今日无需操作"是一等结论，正常渲染**，C1.3）；
6. **交易频次行（固定显示）**：本月已交易 N 笔（上月 M 笔）· 本月换手率 · 非计划交易 K 笔（C1.1）。

盘前增量页（07:30 生成，3–5 行）：隔夜美股 / 期指 / 隔夜重大消息 + 一句"昨晚的计划是否需要调整"。

**热点段规则（C1.2）**：只描述市场结构（资金往哪类资产集中、集中度多高），**不输出可买标的清单**；且仅在晚报出现。LLM 生成段与规则生成段用不同标记区分（C13）。

### M4 交易参考决策（信号清单 + 触发规则，无加权总分）

**核心原则：不输出指令式"买入/卖出"；不设无法验证的加权总分（C7）。**

- **信号清单（规则触发，替代五维加权）**：每条信号独立可解释、可逐条统计历史命中率：
  - 趋势：MA20 上穿/跌破 MA60；MA20 上穿/跌破 MA250 等；
  - 资金：主力连续 3 日净流入/净流出；北向连续增减持；
  - 风险：10 日内有解禁、大额减持、立案调查；
  - 状态归纳：趋势（上涨/震荡/下跌）、资金（流入/流出/平衡）、风险（低/中/高）由**触发信号归纳**得出，不靠加权分；
- **触发规则 → 条件式参考建议**（分持仓/空仓/已有盈利视角）："跌破 20 日线 → 风险关注""回踩企稳且量能不缩 → 可关注""涨幅超 20% → 关注止盈"，附观察点；
- **排序**：需要对自选股排序时用**触发信号计数**，不用加权分；
- **决策方案档位（作用对象变更，C2）**：保守/稳健/激进的主要作用对象从"评分权重"改为**仓位上限与集中度阈值**（如仓位上限 30%/50%/80%、单票上限、行业集中度上限）——权重档位无法验证，而仓位与集中度阈值用户可直接感知、自行校准；
- **决策留痕**：每次信号与建议连同当时的市场快照入库，复盘对照实际走势统计命中率；
- **模型/策略接口（预留，C12）**：统一 DecisionProvider 接口保留设计，但**累计 150 笔交易且 C5 验收通过前不启动**——先有被验证的信号体系，才有值得插件化的东西；
- **免责声明**：固定携带"仅供参考，不构成投资建议"。

**LLM 边界（C13，可机械检查的溯源约束）**——替代 v0.5"只解释不判断"（该表述语义上不可执行："持续性较强"既是解释也是判断，与 M2 要求的"结论"自相矛盾）：
1. LLM 输出的每一句话必须携带输入 `source_id`，后处理丢弃挂不上来源的句子；
2. LLM 产出的任何前瞻性表述统一标 `hypothesis = true`，**强制进入 C6 验证流水线**打分；
3. 日报中 LLM 生成段与规则生成段用不同标记区分。

### M5 交易复盘（核心壁垒：纪律指标优先）

**复盘是本项目长期价值最高的部分。核心保障是"事前记录"，否则归因测量的是后视偏差而不是决策质量。**

1. **交易记录（C3/C19）**：
   - **主入口 = 盘前预先承诺**：开盘前用 `note` 命令记录"今天打算买什么 / 为什么 / 目标 / 止损"，收盘后与实际成交自动比对——比事后记录摩擦更低，且直接产出"按计划执行率"与"非计划交易笔数"；
   - `reason_type / reason_note / plan_target / stop_loss` 四字段在成交 **T+1 后锁定，不可修改**（`reason_recorded_at` 记录填写时间）；
   - 晚于成交 24 小时补录的记录标 `post_hoc = true`，可查看但**从所有归因统计样本中剔除**；
   - 券商 CSV 职责收窄为**对账与补全成交价/手续费**，不作为理由字段的录入入口；
2. **买入理由分类（3 类，C4）**：趋势 / 事件 / 情绪（不再分 5 类——分类越细样本越稀薄）；
3. **纪律指标（复盘第一输出，C4）**：是否按计划执行、是否事前设了止损、是否真的止损了、是否追高、非计划交易笔数——每笔可独立判定（二值事实），**不需要统计功效就有信息量，是第一年唯一可信的复盘输出**；
4. **盈亏来源归因（样本闸门，C4）**：单类样本 **< 20 笔时只列明细、不输出归因结论**，页面显式打印"样本不足，不做归因"——个人年交易 50–150 笔分 3 类后每类仍可能个位数，带正负号的百分比会诱导基于噪音改变行为；
5. **买卖点回看**：K 线标注实际买卖点（M0 后：脚本生成静态图片嵌入 Markdown）；
6. **投资风格画像（C12）**：**累计 150 笔交易前不启动**——风格标签是身份标签，比百分比更难质疑、更易自我实现；样本不足时生成画像等于给用户一个基于运气的自我认知；
7. **复盘报告**：周报（纪律指标为主）+ 月度复盘 + "改进清单"。

| 合规 | 遵守数据源条款、频率控制；全量免责声明；不荐股/不自动交易；**财联社源属灰色区域：仅限个人本地自用，不分发、不二次发布、公开仓库不包含抓取正文；只存标题/时间/链接/自生成摘要**（C15，写入 README 首屏） |
| **行为护栏（C1）** | 见 §2.11 独立章节 |
| **数据质量** | 独立质量检查：价格 ≤ 0 / 交易日无数据 / 涨跌幅超**板块分档**阈值（ST 5%、主板 10%、创业板/科创板 20%、新股首日豁免）；**复权处理**（后复权算指标、不复权展示、除权日豁免跳变检查）（D1/D2） |
| 本地优先 | 数据存本地（SQLite）；LLM 缺失时核心功能仍可用 |
| 可扩展 | 数据源插件化且可配置（接口预留）；信号规则可配置 |
| 性能 | 主报生成 ≤ 3 分钟；采集频率友好（缓存 + 增量）；**M0 串行执行，避免 SQLite 并发锁库（D6）** |
| 稳定性 | 数据源失败自动降级（含 T-1 显式标注）；失败可重试；**交易日历本地缓存兜底（D3）** |
| 可解释 | 信号逐条回溯触发依据；热点结论附数据与依据；**LLM 溯源约束（C13）** |

## 8. MVP 范围界定（M0「两周自用版」，C17）

**M0 目标：两周内用最小成本验证"这份日报是否改善行为、值得每天读"。**

**M0 包含**：
- 单脚本 + 三个输入文件（`watchlist.yaml` / `positions.yaml` / `trades.csv`）；
- **仅用 akshare** 拉日线、主要指数、涨跌家数、成交额；
- 输出一份 `daily.md`：市场概况 + **账户体检** + 自选异动 + **昨日结论验证** + 交易频次行；
- 一条 `note` 命令（10 秒记录盘前计划 / 交易理由 = C3 最小实现）；
- 一条 `read` 命令（记录当日哪段有用 = C5 最小实现）；
- 质量检查只做三条（价格 ≤ 0 / 交易日无数据 / 涨跌幅超板块上限）；
- 三张表（`quotes` / `trades` / `notes`）；
- 手动运行，不做调度。

**M0 不含**：全球市场（第二周若 akshare 全球接口顺利再加）、财联社源（第二周视 read 数据决定，C17.3 折中）、晨报/午报/推送/调度器、信号规则对外输出、DecisionProvider、任何 Web 栈、任何 LLM 调用、完整 schema。

**M0 退出条件**：连续 **20 个交易日**生成成功率 ≥ 90% 且每日有 `read` 记录；按 C5 第 8 条裁剪段落；据裁剪结果决定下一阶段优先级。**Phase 2/3 的时间表在 M0 结束前不预先制定**——M0 结束时会有 20 个交易日的真实使用数据，届时制定的计划质量远高于现在。

## 9. 里程碑（按价值密度推进，C17）

| 阶段 | 周期 | 目标 |
| --- | --- | --- |
| M0「两周自用版」 | 第 1–2 周 | daily.md + note + read，akshare 单源，手动运行（含 5 交易日连续运行验证） |
| M0 评审 | 第 3 周 | 按 read 数据裁剪段落（跳过率 > 50% 直接删除），决定下一阶段优先级 |
| 后续（不预先排期） | M0 后 | 按"价值 ÷ 实现成本"排序推进：高密度项（止损提醒、热点段+验证流水线、静态图买卖点、白/黑名单、周报）→ 中密度项 → 150 笔交易后（风格画像/策略插件/回测/同花顺同步） |

价值密度参考排序（据 C17 论证）：
- **高价值低成本（优先）**：盘前预先承诺记录、账户体检、纪律评分、昨日验证、交易频次行、止损位提醒；
- **中价值**：自选异动、热点段（带验证）、静态图买卖点、来源白/黑名单、Obsidian 组织、周报；
- **低价值/需样本（延后）**：风格画像、策略插件、回测、同花顺同步（≥150 笔）、LLM 溯源压缩、个股详情页。

## 10. 风险与应对

| 风险 | 应对 |

| **工具诱导过度交易（新增，最高优先级）** | 行为护栏（§2.11）+ 行为类成功指标；热点段不出标的清单；"今日无需操作"一等结论 |

## 11. 行为护栏（新增章节，C1）

产品形态自带"诱导高频交易"风险，本节四条为**硬性设计约束**：

1. **交易频次行固定显示**：日报固定行显示"本月已交易 N 笔（上月 M 笔）· 本月换手率 · 非计划交易 K 笔"；
2. **热点段只描述市场结构**：描述资金往哪类资产集中、集中度多高，**不输出可买标的清单**；
3. **"今日无需操作"是一等结论**：正常渲染，不作为异常分支或留白；
4. **产品成功指标（改写）**：按计划执行率 ↑ / 非计划交易笔数 ↓ / 平均持股天数 ↑ / 月交易笔数 ↓——**不是**打开率、不是生成成功次数。§2.10 验收与 M0 评审均以此为准。

## 12. 验收标准（M0）

1. 每天盘后自动生成 `daily.md`（五段 + 交易频次行），5 分钟内读完；
2. **账户体检**：总仓位/单票占比/行业集中度/破止损位持仓/浮盈亏分布/平均持股天数全部可见，与手工核算一致；
3. 前瞻性结论均携带 `prediction`，且按 `verify_rules.yaml` 事前判据完成**昨日验证**；
4. 自选池（watchlist.yaml）/持仓（positions.yaml）更新后日报自动更新；
5. 质量检查生效（异常被标记/拦截，人工抽检 1 周）；
6. 交易记录可录入（含买入理由，T+1 锁定），纪律指标统计与手动核算一致；
7. **价值验收（C5）**：连续 20 个交易日，每天读完日报后记录一行"今天真正有用的是哪一段 / 有没有影响我的操作"（`read` 命令）；
8. **价值验收（C5）**：20 天后按段落统计跳过率，**跳过率 > 50% 的段落直接删除，不做优化、不留开关**（留开关等于不删）。
