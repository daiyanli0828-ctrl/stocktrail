# 技术架构设计

> 配套：[01-产品开发企划](01-产品开发企划.md) · [02-开源方案调研](02-开源方案调研.md)
> 说明：本设计面向 **M0「两周自用版」** 落地，保持"本地优先、数据质量先行、行为护栏、可解释、可配置、可插拔"原则。
> v0.6 变更：① 架构大幅简化（M0 单脚本 + Obsidian，不自建 Web）；② 数据源 akshare 单源起步，全球主备调换（akshare 主 / yfinance 备 / T-1 标注）；③ 决策引擎改为**信号清单 + 触发规则**（删除加权总分与 score_weights.yaml）；④ 质量规则分板块阈值 + 复权处理 + 交易日历本地缓存；⑤ LLM 溯源约束；⑥ M0 精简为 3 表 + 串行写入；⑦ 部署 Windows 计划任务。

## 2. M0 输入输出契约

**输入（3 个文件）**：
- `watchlist.yaml`：自选股代码列表（如 `600519 / 000001 / 300750`）；
- `positions.yaml`：持仓快照（code, shares, avg_cost, opened_at, stop_loss, plan_target）——手动维护，M0 后与 trades 自动核对；
- `trades.csv`：历史成交（对账用；理由字段不由 CSV 导入）。

**输出**：
- `daily.md`：市场概况 / 账户体检 / 自选异动 / 昨日验证 / 明日计划（条件式）/ 交易频次行；
- 盘前增量附页（3–5 行：隔夜美股/期指/隔夜重大消息 + 计划是否需要调整）；
- 均落盘到 Obsidian vault 目录。

**命令**：
- `note "计划内容"`：盘前预先承诺（今天打算买什么/为什么/目标/止损）；成交后 T+1 锁定 reason 四字段；
- `read "段落名 有用/没用"`：C5 价值验收记录。

## 3. 数据源适配与降级链（M1）

- 统一接口 `DataSourceAdapter`：`get_daily_quotes / get_index_snapshot / get_market_breadth / get_news(可选) / get_global_indices(第二周)`；
- **★ M0 核心源**：akshare（日线、指数、涨跌家数、成交额）；
- **全球市场（C14）**：akshare 全球指数接口为主源；yfinance 仅在检测到代理可用时启用（备）；**两源均失败 → 使用上一交易日数据，报头显式标注"全球数据为 T-1，来源 X 失败"**；
- **财联社（C15）**：可选增强；只存标题/时间/链接/自生成摘要，不存原文全文；仅限个人本地自用；
- **用户自定义源**：config 注册（接口预留）；
- **日期归属（D4）**：全库统一存 UTC + 显式 `trade_date` 归属规则（美东→北京 next-day 归属）；夏令时切换周人工核对一次；
- 频率控制：日频拉取；请求间隔 ≥ 0.5s，失败指数退避。

## 4. 调度（C18）

- **M0 阶段：手动运行**（`run_daily` 手动执行，不做调度器、不用 APScheduler 常驻）；
- **M0 后：Windows 计划任务**（`schtasks` 配置盘后 19:00 自动跑；07:30 增量附页）——不用 Docker；
- **交易日历（D3）**：本地缓存年度交易日历 yaml 兜底，在线接口只做增量校正；接口故障时以本地日历判断当天是否运行，避免休市日产出空报告。

## 5. 存储 Schema 草案

**M0 只用三张表**（D5：把尚未验证的设计提前锁死会让日报形态一改就要迁移 schema；段落稳定约 20 交易日后才补全）：

| 表 | 关键字段 | 说明 |
| --- | --- | --- |
| `quotes` | code, trade_date(UTC), open/high/low/close, **adj_close(后复权)**, volume, amount, pct_chg, quality_flag | 唯一索引 (code, trade_date)；指标计算用 adj_close，展示用 close（D1） |
| `trades` | id, code, side, price, shares, ts, **reason_type, reason_note, plan_target, stop_loss, reason_recorded_at, post_hoc** | T+1 后 reason 四字段锁定；post_hoc 剔除归因样本（C3） |
| `notes` | id, ts, kind(plan/trade_reason/read), content, rel_trade_id | note/read 命令落库（C3/C5） |

**M0 后按需补全**（段落稳定后，且对应功能达价值阈值时）：

| 表 | 关键字段 | 说明 |
| --- | --- | --- |
| `positions` | code, shares, avg_cost, opened_at, stop_loss, plan_target, updated_at | 持仓表（C2）；M0 由 trades + positions.yaml 合并计算 |
| `hot_concepts` | date, slot, concept, conclusion, logic, evidence_json, llm_used, **prediction, actual, verdict, verified_at** | 热点结论；prediction 必填（方向/口径/时限），判据读 verify_rules.yaml（C6） |
| `news` | id, source, title, url, published_at, rel_codes, tags, sentiment, importance, **source_trust(trusted/unknown/blocked)** | 只存标题/链接/自生成摘要；黑名单不入库（C11/C15） |
| `market_snapshot` | date, region, index_code/name, close, pct_chg, up/down/flat_count, limit_up/down, turnover | 大盘快照 |
| `decisions` | id, code, date, profile, signals_json, advice_json, evidence_json, snapshot_json | 决策留痕（信号清单制） |
| `review_stats` | period, scope, stats_json | 纪律指标/归因（样本闸门）/风格画像（≥150 笔） |
| `quality_logs` | ts, table, row_key, check_type, severity, detail | 质量日志 |

## 6. 决策引擎（M4 v0.6）：信号清单 + 触发规则

**取消五维加权总分（C7）**——权重凭经验设定、样本量永远不足以验证，却因算出数值产生精确感；保留一个既不对外、又无法验证、又需持续调参的中间层是纯负债。替代方案：

```yaml
# config/signal_rules.yaml
signals:
  - id: trend_ma20_cross_ma60_up
    desc: "MA20 上穿 MA60"
    type: trend
    compute: "adj_close 的 MA20 上穿 MA60"
  - id: trend_ma20_cross_ma60_down
    desc: "MA20 跌破 MA60"
    type: trend
  - id: capital_main_inflow_3d
    desc: "主力连续 3 日净流入"
    type: capital
  - id: risk_unlock_10d
    desc: "10 日内有限售解禁"
    type: risk
triggers:
  - id: t_break_ma20
    when: "close < MA20"
    advice:
      - {scope: "持仓中", action: "风险关注", condition: "跌破 20 日线"}
      - {scope: "空仓", action: "等待确认"}
```

- **输出**：状态（趋势/资金/风险，由触发信号**归纳**）+ 信号清单（逐条注明触发依据）+ 条件式建议（三视角）+ 观察点；**无总分、无评级**；
- **排序**：需要排序时用**触发信号计数**；
- **方案档位（作用对象变更，C2）**：保守/稳健/激进配置的是**仓位上限、单票占比上限、行业集中度上限**（用于账户体检对比），不再是评分权重；
- **留痕**：`decisions` 存 signals_json + 市场快照；每条信号可逐条统计历史命中率，接入 C6 验证流水线；
- **DecisionProvider 接口**：设计保留，**累计 150 笔交易且 C5 验收通过前不实现**（C12）。

## 7. 质量检查（app/quality）

M0 只做三条；规则配置化（`config/quality_rules.yaml`）：

| 检查项 | 规则（v0.6） | 处理 |
| --- | --- | --- |
| 价格非法 | 价格 ≤ 0 | 拦截 |
| 交易日缺数据 | 本地交易日历判定为交易日但无行情 | 标记 + 报告标注 |
| 涨跌幅超阈值 | **按板块分档**（D2）：ST 5% / 主板 10% / 创业板·科创板 20% / 新股首日豁免 / 退市整理 10% | 标记 + 拦截（可复核） |

- **复权处理（D1）**：后复权价用于全部指标计算，不复权价用于展示；除权日从跳变检查中豁免；
- 全部异常落 `quality_logs`；日报底部标注数据质量状态。

## 8. LLM 层（C13：可机械检查的溯源约束）

- M0 **不调用任何 LLM**；
- 后续接入时执行三条代码级约束：
  1. LLM 输出的每句话必须携带输入 `source_id`，后处理丢弃挂不上来源的句子；
  2. LLM 前瞻性表述统一标 `hypothesis = true`，强制进入 C6 验证流水线；
  3. 日报中 LLM 段与规则段用不同标记区分；
- 用途限定：文本压缩 / 新闻归因 / 复盘总结——"只做可溯源的文本压缩"。

## 11. 关键设计决策（v0.6）

1. **M0 单脚本、单源、三张表**：按价值密度推进，不提前锁死设计（C17/D5）；
2. **行为护栏优先于功能丰富度**：交易频次行、不出标的清单、无需操作是一等结论（C1）；
3. **事前记录是复盘可信的前提**：盘前预先承诺 + T+1 锁定 + post_hoc 剔除（C3）；
4. **不做无法验证的计算**：无加权总分（C7）、无星级权重（C11）、归因样本闸门（C4）；
5. **可机械检查的 LLM 约束**：source_id / hypothesis / 段标记（C13）；
6. **全球数据诚实降级**：akshare 主 + yfinance 备 + T-1 显式标注（C14）；
7. **质量规则按真实市场规则分档**：复权、分板块涨跌停阈值、交易日历本地缓存（D1–D3）；
8. **展示用 Obsidian，不自建前端**（C9）；**盘中不做**（C10）；
9. **复盘是护城河**：纪律指标第一输出，归因样本达标后解锁（C4）。
