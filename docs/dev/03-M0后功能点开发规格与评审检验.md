# M0 后功能点开发规格与评审检验（价值清单）

> M0 结束前**不排期**。每个功能点给出：**触发条件**（何时才做）→ **开发规格要点**（给 v4-flash）→ **评审检验要点**（给 v4-pro）→ **用户确认项**（如需要）。
> 按价值密度分组：高 → 中 → 低；「不做」组为永久取消项（评审方按 D 级检查打回任何死灰复燃的实现）。

---

## 高价值组

### P-01 盘中止损位提醒（C10 唯一例外）

- **触发条件**：M0 完成后，用户确认需要（企划 §13 待确认第 2 项）。
- **开发规格要点**：仅对 `positions` 中**设有 stop_loss** 的持仓生效；盘中价格（akshare 实时接口，低频轮询 ≥5 分钟）跌破 stop_loss → 桌面/邮件提示一次，措辞执行用户过去的决定："你设定的止损位已触发，请按计划处理"；不输出任何其他市场信息。
- **评审检验要点**：A 级——代码仅含止损触发逻辑，无其他盘中异动/公告/全市场提醒（C10）；C 级——提示措辞无新建议；B 级——构造模拟跌破/未跌破场景验证触发与去重（同日不重复提醒）。
- **用户确认项**：提醒渠道（桌面通知/邮件）。

### P-02 热点段（晚报）+ 完整验证流水线

- **触发条件**：F-09 昨日验证流水线在 M0 跑通（有判据、有 20 日命中率基线）。
- **开发规格要点**：规则初筛候选概念（涨幅/振幅/换手/资金流/连板梯队）→ 生成"结论 + 板块真实数据 + 依据"，每条结论强制带 `prediction`（C6）；晚报输出，只描述市场结构（C1.2）；周报输出命中率对比基线。
- **评审检验要点**：C 级——无标的清单；prediction 必填；D 级——判据仍仅存 verify_rules.yaml；B 级——抽 3 条结论核对数据与判据计算。
- **用户确认项**：热点段呈现形式。

### P-03 纪律指标周报

- **触发条件**：trades/notes 数据积累 ≥ 1 个月。
- **开发规格要点**：按计划执行率 / 非计划笔数 / 事前设止损率 / 止损执行率 / 追高次数（买入价 > 当日均价 +2% 定义）——每笔独立判定（C4）；周报输出 + 趋势线（4 周滚动）。
- **评审检验要点**：B 级——抽 1 周与手工核算一致；追高定义在文档/config 中明示且可复核。
- **用户确认项**：追高阈值定义。

### P-04 来源白/黑名单过滤

- **触发条件**：接入财联社或东财新闻时同步实现（与 F-11 联动）。
- **开发规格要点**：`source_trust ∈ {trusted, unknown, blocked}` 二值过滤，黑名单不入库（C11）；白名单初始内置（财联社/官方公告类），用户可增改。
- **评审检验要点**：A 级——过滤在入库前生效；黑名单测试生效；无星级/权重残留。
- **用户确认项**：初始白名单清单。

## 中价值组

### P-05 静态图买卖点标注

- **触发条件**：read 数据显示"看图复盘"为高频需求（C9 保留判断）。
- **开发规格要点**：脚本生成个股 K 线静态图（matplotlib），标注实际买卖点与当时的 note 理由；嵌入 daily.md/复盘页 Markdown；**不自建前端**。
- **评审检验要点**：B 级——抽 1 只股票买卖点标注与 trades 一致；D 级——无 Web 栈引入。
- **用户确认项**：图样式。

### P-06 Windows 计划任务自动化

- **触发条件**：M0 验证日报有价值后。
- **开发规格要点**：`schtasks` 注册三个任务：19:00 `run_daily`、07:30 增量附页、盘中每 5 分钟 `stop_watch`；休市日自动跳过（本地交易日历，D3）；日志落盘；不用 Docker/APScheduler 常驻（C18）；**失败通知**：任务退出码非 0 时桌面通知（与 P-01 同通道、无第三方依赖）——通知层为过渡方案，整体产品形态（软件/网页/小程序）确定后可替换（用户 2026-08-31 拍板：通知方式待定，当前以桌面通知过渡）。
- **评审检验要点**：B 级——模拟休市日验证不运行；失败重试与通知存在。
- **用户确认项**：运行时间点（已确认 19:00/07:30/5 分钟）。

### P-07 盈亏来源归因（3 类，样本闸门）

- **触发条件**：单类理由样本 ≥ 20 笔（C4）。
- **开发规格要点**：按 reason_type（趋势/事件/情绪）分组统计收益；**单类 < 20 笔只列明细并显式打印"样本不足，不做归因"**；不输出百分比结论；post_hoc 样本已剔除（C3）。
- **评审检验要点**：B 级——构造 25 笔样本组与 Excel 核算一致；闸门逻辑测试（19 笔触发"样本不足"）；D 级——无 post_hoc 混入。
- **用户确认项**：归因报告口径。

## 低价值组（需样本/需验证后）

### P-08 LLM 溯源压缩（C13 三约束）

- **触发条件**：出现明确的高价值文本场景（如周报总结、新闻归因）且用户同意接 LLM。
- **开发规格要点**：每句挂 `source_id`，后处理丢弃挂不上来源的句子；前瞻表述标 `hypothesis=true` 强制进验证流水线；LLM 段与规则段标记区分；OpenAI 兼容 API/Ollama，未配置自动回退规则模板。
- **评审检验要点**：A 级——三约束均可代码检查（丢句逻辑、hypothesis 路由、标记渲染）；无 LLM 时全功能可用。

### P-09 投资风格画像

- **触发条件**：**累计 ≥ 150 笔交易 且 C5 验收通过**（C12）。
- **开发规格要点**：持股周期分布、盈利/亏损主因、风格标签；输出带置信说明（样本量、分布宽度）；画像更新频次季度。
- **评审检验要点**：D 级——未达 150 笔不启动（代码中有硬闸门）；输出无确定性身份表述（"你是趋势型选手"类措辞须加"基于 N 笔样本"前缀）。

### P-10 DecisionProvider 策略插件 / 回测

- **触发条件**：信号体系经命中率验证后（C12）。
- **开发规格要点**：统一接口 `decide(ctx)`；用户外接策略一个 Python 类注册即用；回测仅回放历史信号与验证判据，不做策略优化承诺。
- **评审检验要点**：D 级——插件不改变规则引擎输出；LLM 仍只做解释。

### P-11 同花顺同步（自选/持仓只读）

- **触发条件**：累计 ≥ 150 笔交易后评估（C12）。
- **开发规格要点**：ths-favorite 自选同步（只读）；客户端只读自动化读取持仓/资金——**仅展示与复盘，无下单能力**。
- **评审检验要点**：D 级——代码无任何下单/委托接口；凭证仅存本地。
